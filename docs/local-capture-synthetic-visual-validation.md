It belongs only to `StorageValidationTests`; it is not a production composition or a default app entry point.

Its body, controls, MapKit subview, and production host call sites are unchanged. The inert validation app compiles the host source without constructing that production host; its entry point remains unchanged. The normal app does not include the synthetic fixture or test source.

One one-minute Swift Testing case is authored for a fixed UTC day: history starts empty, selecting the day returns three points, and Next replaces them with two different points and a terminal cursor. The stopped snapshot has revision 2, no active epoch, and a matching Stop receipt for epoch revision 1. The test checks query/cursor continuity and zero forbidden storage, location, authorization, service-status, runtime-handle, and maintenance actions. The reusable handle exposes the actual view/model, expected inputs, an audit, and explicit disposal for a later separately admitted visual check.

Only source/patch integrity, deterministic fixture data, exact target memberships, and preserved source regions have been checked. Swift syntax/type/concurrency correctness, test discovery/execution, direct access to uninstalled SwiftUI State, app compilation, screen rendering, controls, screenshots, MapKit basemap/network effects, and device behavior remain unverified. No native tool, app, simulator, or device was invoked for this checkpoint.

Its scheme enables test timeouts with a 60-second allowance; a future frozen command must also explicitly bind `-test-timeouts-enabled YES -default-test-execution-time-allowance 60 -maximum-test-execution-time-allowance 60`, an admitted destination and fresh result root. This document supplies no execution authority or runnable admission.

The entry requires exactly one active scene and one visible keyed host window, temporarily hosts the actual screen, and retains three named XCTest image attachments alongside data/receipt/zero-action assertions. Ambiguous hosting or failed/nonempty hierarchy capture throws; teardown detaches the temporary controller/window, restores the original inert window and disposes the fixture. It does not tap capture or maintenance controls or write screenshot paths. Data assertions and named attachments alone do not prove that SwiftUI visibly refreshed, the expected content was onscreen, or that the map rendered correctly; those require actual admitted execution and visual inspection. The real MapKit view may initiate tile/network activity, so that effect must be covered separately before any render. Never substitute default app/legacy initialization or live providers/store.
