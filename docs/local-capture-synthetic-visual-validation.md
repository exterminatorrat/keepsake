# Synthetic local-capture screen source preparation

The reusable `LocalCaptureExperimentSyntheticVisualFixture` composes the existing experiment screen and consumer model with in-memory persistence/history, denied static authorization, a never-live location source, and instrumented no-op runtime dependencies. It belongs only to `StorageValidationTests`; it is not a production composition or a default app entry point.

The existing screen accepts an optional calendar and clock, retaining current-calendar/current-time production defaults. Its body, controls, MapKit subview, and production host call sites are unchanged. The inert validation app compiles the host source without constructing that production host; its entry point remains unchanged. The normal app does not include the synthetic fixture or test source.

One one-minute Swift Testing case is authored for a fixed UTC day: history starts empty, selecting the day returns three points, and Next replaces them with two different points and a terminal cursor. The stopped snapshot has revision 2, no active epoch, and a matching Stop receipt for epoch revision 1. The test checks query/cursor continuity and zero forbidden storage, location, authorization, service-status, runtime-handle, and maintenance actions. The reusable handle exposes the actual view/model, expected inputs, an audit, and explicit disposal for a later separately admitted visual check.

Only source/patch integrity, deterministic fixture data, exact target memberships, and preserved source regions have been checked. Swift syntax/type/concurrency correctness, test discovery/execution, direct access to uninstalled SwiftUI State, app compilation, screen rendering, controls, screenshots, MapKit basemap/network effects, and device behavior remain unverified. No native tool, app, simulator, or device was invoked for this checkpoint. A future render must use this inert test composition, never the default app launch or real providers/store; it requires separate bounded authorization and an appropriate render entry.

This branch is separate from the sealed consumer verification inputs and from the resource-fixture branch. It does not change the sealed seven-suite 96-declaration/99-invocation oracle, authorize execution, enable the experiment, switch storage, import legacy data, connect a backend, or permit activation or merging.
