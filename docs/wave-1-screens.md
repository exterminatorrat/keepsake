Production services explicitly report that real sign-in is not configured. Entering an email must not synthesize an account or a group. No SDK, key, backend migration, Auth request or demo sign-in has been added.

The source includes minimal Email/Code presentation, restoring/configuration/error states, a private solo-group name form and the five-tab Groups shell. The reference surfaces are G01/G02/G03, self-only M01/M02 and S00/minimal Account. Features outside this slice explain that they are unavailable. These are testable state seams, **not** complete Auth integration, Keychain restoration, durable pending-create storage, database membership/RLS enforcement or device-grade account isolation. Those require the planned real adapters and authorized backend acceptance. No route archive is opened, assigned to an account, migrated or deleted.

## Reference correction and capture contract

### Source/API review of native map attribution

The admitted ba64801 checkpoint compiled/passed its 20 selected declarations/30 invocations and captured 15 readable poses/readiness records. Its attribution visibility was not accepted. Source review then established a real layout/interaction problem in the production view composition, independently of those pixels: the map ignored all container safe areas while opaque sheets/error/member cards were bottom-aligned ZStack siblings; the entire map also had hit testing disabled and was hidden from accessibility. Thus bottom UI did not reserve the map's system-control region, and its native Legal affordance could not be activated through the map. This is a source defect, not a legal-compliance verdict or a claim that capture/tile behavior was the only cause of absent pixels.

Apple's [Meet MapKit for SwiftUI](https://developer.apple.com/videos/play/wwdc2023/10043/) explicitly recommends `safeAreaInset` so app UI does not obscure system-provided controls “such as the Apple Maps logo and Legal link.” The public SDK interface and [standard map-style documentation](https://developer.apple.com/documentation/mapkit/mapstyle/standard(elevation:emphasis:pointsofinterest:showstraffic:)) were read as text; no compiler, SDK execution or native probe was used for this review.

The narrow correction makes the real native map own its bottom content through `safeAreaInset(edge: .bottom, spacing: 0)`. Group sheets/compact strip, inset member card and offline error card use that same mechanism. The existing floating-button footprint is included in the reserved content so it cannot simply replace the sheet as an obstruction; its 106+10-point resting and 48+12-point selector footprints are unchanged. The outer tab inset remains; only the top container safe area is ignored. Non-map detail/settings/account surfaces no longer instantiate a covered map behind their opaque content.

`interactionModes: []` still disables map manipulation, but blanket hit-test/accessibility exclusions are removed so MapKit keeps its own legal interaction/accessibility. Whole-map grayscale/dark overlays are replaced by native `standard` style's `muted` feature emphasis for subdued states, without filtering or painting over legal controls. No fabricated attribution, negative clipping, private subview lookup or replacement map is introduced. Actual legal visibility/activation, capture-surface behavior and small/AX adaptation still need authorized native evidence; the prior ba64801 pass does not validate this later source-only correction.

The reported +3/−3-point image edges are **not automatically a violated layout contract**. `GroupSheetLayout` specifies proportional heights in the available content viewport, not absolute screenshot y coordinates: `height = viewport × referenceHeight / 720`, subject to header/accessibility clamps. Native safe areas/tab geometry need not reproduce the PDF's drawn 720-point interior even when the full screen is 402×874 points. For example, a 712-point viewport ending at y774 predicts resting/expanded/selector tops 449.64/232.09/578.20; this is an illustrative evaluation, not a retrospectively measured UIKit frame. The old readiness JSON records stability counts, not those actual frames. Integer brightness jumps at a rounded/antialiased raster edge are a separate diagnostic. No frame-contract defect was established, so the detent constants/function/tests were left unchanged rather than tuned to that heuristic.

For the six map-visible poses, the test finds the owned hierarchy's public `MKMapView` and temporarily forwards its delegate through a test-only observer. The original delegate is pinned, unrelated optional selectors are forwarded, and teardown restores it only if the test still owns that delegate slot. A delegate change, missing/ambiguous public map, loading error or 12-second deadline cannot pass readiness. A loading-complete callback or elapsed frames alone is not tile readiness: the required signal is `mapViewDidFinishRenderingMap(... fullyRendered: true)`, followed by stable geometry frames. This SDK-specific observation path and Swift concurrency/Objective-C bridge remain uncompiled/unrun risks.

The observer's sole `nonisolated(unsafe)` field is an immutable, strongly pinned downstream delegate, read only by NSObject selector-query/forwarding overrides. UI mutation, callback processing and teardown stay on MainActor; MapKit documents delegate delivery on the main thread. No mutable capture state crosses that bridge. Remove the escape hatch when SDK selector isolation permits a checked equivalent; it must not spread to production or suppress other diagnostics. First authorized compilation must validate this boundary rather than treating the source review as a concurrency pass.

The original draw assertion is retained and a stricter readiness assertion added. Every attempted pose still attaches its actual image and a `READINESS-<label>` JSON state even when readiness fails, so partial/unavailable/timeout evidence is not erased. Readiness records contain appearance/layout/map/deadline state and sanitized error domain/code, not arbitrary network error details. A successful callback/draw still needs human inspection of map content, attribution and overlay fidelity.
